# 加班日历 📅

> **中文** ｜ [English](README.en.md)

月历式加班记录。点一天，填你在工作的时间段，剩下的交给它算。

![月历](docs/month.png)

## 特性

- 🗓 **月历视图** —— 一屏看完一个月，哪天有加班一眼就看得出来
- ⚙️ **首次使用向导** —— 自己定「周几上班」和「上午 / 下午几点到几点」
- 🧮 **自动裁剪** —— 只填你在工作的时间段，正常上班那几段自动扣掉
- 🇨🇳 **节假日联网**（可选）—— 拉取法定假日和调休，三个数据源依次降级
- 📊 **导出 Excel** —— 当月明细 + 合计，一键存成 `.xlsx`
- 📌 **与便利贴联动** —— 读取「便利贴」的待办，也能一键启动它
- 🎨 **5 套马卡龙配色** —— 草莓 / 薄荷 / 薰衣草 / 柠檬 / 蓝莓
- ✨ **一堆小动效** —— 翻月滑动、格子错开淡入、今天的光环、保存提示胶囊

## 快速开始

```bash
git clone <你的仓库地址>
cd overtime-calendar
npm install
npm run dev
```

> 需要 Node 18 以上。`npm run dev` 会同时拉起 Vite 和 Electron，改渲染层代码有热更新。

## 首次使用

第一次打开会弹一个向导，问你三件事：

1. **每周哪几天上班** —— 点一下切换，默认周一到周六
2. **上午几点到几点**
3. **下午几点到几点**

填完点「开始使用」就存下来了。不想现在填可以点「用默认作息」直接进。之后想改，点右上角的 **⚙️** 随时重开；改完立刻生效，**已经记好的加班会按新作息重新折算**。

## 工时规则

作息是**你自己定的**，规则本身固定：

| 项 | 规则 |
| --- | --- |
| 上班日 | 向导里选的那几天（默认周一到周六） |
| 正常时段 | 向导里填的上午段 + 下午段（默认 08:00-12:00、14:00-18:00） |
| 加班 | 正常时段**以外**的时间 |
| 休息日 | 没选作上班的日子，**整天都算加班** |
| 法定假日 | 放假，**整天都算加班** |
| 调休上班日 | 按普通工作日算 |
| 请假 | 单独记录，不参与加班折算 |

当前生效的作息会一直摆在底部统计栏右侧，不用翻设置就能确认按什么规则在算。

### 自动裁剪

你填的是「**你在工作的时间段**」，系统会按你的作息自动扣掉正常上班时段。下面以默认作息（08:00-12:00、14:00-18:00）举例：

| 你填的 | 实际算成的加班 | 为什么 |
| --- | --- | --- |
| 周四 `18:00-21:30` | **3 小时 30 分** | 完全在正常时段之外 |
| 周四 `17:00-20:00` | **2 小时** | 17:00-18:00 是正常上班，不算 |
| 周四 `07:00-09:00` | **1 小时** | 08:00-09:00 是正常上班，不算 |
| 周四 `09:00-11:00` | **0** | 全落在正常时段里 |
| 周日 `09:00-18:00` | **9 小时** | 休息日不裁剪，填多少算多少 |

> 午休时段（默认 12:00-14:00）在正常上班时段之外，所以如果你把午休也填进去，那段时间会算作加班 —— 因为填进去就等于「那会儿在工作」。
>
> 换成自定义作息后，这套裁剪逻辑自动跟着走：比如改成 09:00-18:00 单段，那 08:00-09:00 和 18:00 之后都算加班，而 12:00-13:00 落在上班时段内就不算。

## 怎么用

1. **点日历上任意一天** → 右侧滑出编辑面板
2. 面板里可以填：
   - **加班时段**：最多 6 段，每段即时显示按规则折算后的时长；算出来是 0 的会灰掉提示「不算加班」
   - **请假**：勾上后选类型（事假 / 病假 / 年假 / 调休 / 婚假 / 产假 / 其他）+ 小时数
   - **备注**：比如「项目上线」
3. 点「保存」；想清掉就点「清空这天」
4. 底部实时显示本月合计：加班小时数、请假小时数、工作日天数

**日期格的读法：**

- 白色 = 工作日，浅粉 = 休息日，深粉 = 法定假日，浅蓝 = 调休上班
- 右下角粉色胶囊 `+3h` = 这天有加班
- 白色胶囊 `年假` = 这天有请假
- 格子上有红字（如「国庆节」）= 节假日名称
- 有一圈扩散光环的是今天

## 联网获取节假日（可选）

**不联网也能用** —— 默认只按你设定的作息算。

想让它认识法定假日和调休，点右上角的 **☁** 按钮，会去拉当年的数据：

1. **jsDelivr** 上的 holiday-cn 数据（国内访问快）
2. 失败退到 **GitHub Raw** 上的同一份
3. 再失败退到 **timor.tech** 的 API

拿到的数据会存本地，之后离线也能用。同步过之后，日历上会直接标出「国庆节」「春节调休」这类名称，并且这些天的加班规则也跟着变（假日全天算加班、调休日按工作日算）。

> 数据来自公开的国务院放假安排整理，跨年时记得同步一下新年份。

## 配色

点右上角的 **🎨** 循环切换 5 套马卡龙配色：草莓 / 薄荷 / 薰衣草 / 柠檬 / 蓝莓。

整张纸、文字、加班标记、节假日底色、图钉、按钮都会跟着换，选中的配色会记住。

## 导出 Excel

点右上角的 **📊**，把当月记录导出成 `.xlsx`：

- 明细列：日期 / 星期 / 性质 / 加班时段 / 加班时长 / 请假类型 / 请假时长 / 备注
- **只导出有记录的日子**，空的日期不占行，表格干净
- 末尾自动补一行**合计**（工作日数、加班总额、请假总额）
- 表头冻结 + 淡粉底色，打开就能看

保存位置自己选，默认落在「文档」目录，文件名形如 `加班记录-2026-09.xlsx`。

> 工时是**在渲染进程算好再交给主进程**的，主进程只负责把行数据铺进表格。这样导出的数字和界面上看到的必然一致 —— 如果两边各实现一套规则，迟早会算出不一样的数，还很难查。

## 与便利贴联动

点右上角的 **📌** 打开便利贴面板：

| 能力 | 说明 |
| --- | --- |
| **读** | 自动找到便利贴的待办，分成「待办 / 已完成」两组显示 |
| **开** | 底部「打开便利贴」按钮，一键启动便利贴程序 |
| **换** | 点「指定程序」选便利贴的 exe 位置，记住下次直接用 |
| **刷新** | 便利贴改了内容，点一下重新读 |

数据来源会依次尝试三个位置，谁有就用谁：

```
%APPDATA%\马卡龙便利贴\sticky-note-state.json    ← 独立便利贴
%APPDATA%\macaron-sticky-notes\...              ← 独立便利贴（开发版）
%APPDATA%\马卡龙套件\suite-state.json            ← 套件里的便利贴模块
```

> 便利贴的数据是**只读**的 —— 日历只拿来看，不会改动你的待办。
>
> 如果三个位置都没有，面板会提示「未连接」并告诉你怎么设置，不会报错。

## 动效

- 翻月：整块网格按方向滑入滑出
- 进月：42 个格子按顺序错开淡入，像多米诺铺开
- 悬停：格子轻轻抬起并放大 3.5%
- 点击：按下回弹
- 今天：一圈缓慢扩散的光环
- 加班标记：添加时从小弹到大
- 编辑面板：从右侧滑出，日历区跟着收窄
- 保存成功：底部浮出一条提示胶囊

## 技术架构

Electron 主进程负责数据读写和联网，渲染进程只管画。

```
渲染进程 (Vue 3 + SCSS)             主进程 (Electron)
  │                                   │
  │  点一天 → 填时段                   │
  │ ──── IPC: cal:save-day ─────────► │  校验 + 落盘
  │                                   │
  │ ──── IPC: cal:sync-holidays ────► │  net.fetch 三个源依次尝试
  │ ◄─── 节假日数据 ────────────────── │  缓存到本地
  │                                   │
  │  工时计算（纯前端，见 worktime.js） │
```

**工时计算是纯函数**，放在 `src/shared/worktime.js`，不依赖 Electron，所以能直接用 Node 跑单元测试：

```bash
npm test
```

34 项断言覆盖了时段裁剪、跨午休、休息日不裁剪、**自定义作息**、脏数据过滤、闰年网格、月度汇总等边界情况。

## 踩坑记录

开发过程中踩过的坑，都记在这儿了：

- **Vue 的响应式对象不能直接过 IPC**。`ref` / `reactive` 里拿出来的是 **Proxy**，丢给 `ipcRenderer.invoke` 会抛 `An object could not be cloned`。要命的是如果这个异常没被 catch，界面表现就是「**点了按钮没反应**」，查起来极费劲。所有跨进程参数现在统一走 `toPlain()`（`JSON.parse(JSON.stringify())`）。**「开始使用」和「保存某天」都栽在这上面过。**
- **全屏遮罩会把标题栏一起盖住**。向导遮罩原本是 `inset: 0`，连右上角的 ✕ 都点不到 —— 用户会被**卡死在弹窗里出不去**，只能去任务管理器结束进程。遮罩要 `top: 54px` 让开标题栏，另外首次使用也补了个「用默认作息」的退路。
- **回归测试要用真实鼠标事件**。`element.click()` 会绕过命中测试、直接派发事件，测不出「按钮被别的元素挡住」。改用 `webContents.sendInputEvent` 才揪出上面那个遮罩问题；这两个 bug 都是补了 UI 级测试之后才暴露的。
- **自检「跑完了但没有任何输出」**：`requestSingleInstanceLock()` 会让第二个实例**静默退出**（exit 0，什么都不做）。如果软件正开着，`npm run smoke` / `npm run shot` 就会一点输出都没有，看起来像卡死。现在自检模式会把自己切到独立的 userData，不再和运行中的实例抢锁。
- **BOM 会让 `JSON.parse` 直接抛错**。PowerShell 的 `Set-Content -Encoding UTF8` 写出来的文件带 BOM，读便利贴数据时会解析失败。读取端统一先 `.replace(/^\uFEFF/, '')` 剥一层更稳。
- **图钉被裁掉**：纸片用了 `overflow: hidden`（为了让内部滚动内容被圆角裁切），而图钉的 `top` 是负值、想探出纸片顶部，结果被整个裁掉了 —— 看上去像「图钉没了」。把图钉移到纸片**外面**、由外层容器负责定位就好了。
- **日期数字被裁**：手写体（Segoe Print / 楷体）的字面比常规字体高，`line-height: 1.1` 配合 `overflow: hidden` 会把数字底部切掉，得给到 1.3。
- **`<input type="time">` 宽度**：要留出右侧表盘图标的位置，「18:00」至少需要 92px，窄了会显示成「18:0(」。
- **Node 跑 ESM 的警告**：`worktime.js` 是 ESM 但 package.json 没声明 `"type": "module"`（声明了 Electron 主进程的 `require` 会炸），跑测试时用 `--disable-warning=MODULE_TYPELESS_PACKAGE_JSON` 压掉。
- **Vite 必须显式绑 IPv4**：默认 `localhost` 可能解析成 `::1`，dev 脚本里 `wait-on` 等的是 `127.0.0.1`，对不上 Electron 就永远不启动。

## 已知限制

- 打包目标只有 Windows（`nsis` + `portable`）。要出 macOS / Linux 包，改 `package.json` 里 `build.win` 为对应平台即可，代码本身是跨平台的。
- 「与便利贴联动」依赖 Windows 的 `%APPDATA%` 路径和 `.exe`，换平台需要另做适配。
- 联网拉的是第三方整理的节假日数据，不保证与官方公告 100% 同步。
-
